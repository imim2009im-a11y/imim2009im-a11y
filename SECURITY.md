# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in public Issues. Use the repository's private vulnerability reporting flow when available: https://github.com/imim2009im-a11y/imim2009im-a11y/security/advisories/new

Include the affected component, reproduction conditions, impact, and a safe contact method. Do not include credentials, tokens, private keys, or personal data in the report.

## Scope and principles

Reports involving source integrity, dependencies, GitHub Actions, authentication, authorization, secrets, or user data are in scope. Do not perform denial-of-service, social-engineering, or unauthorized access testing.

The project follows least privilege, dependency review, secret scanning, and evidence-based verification before declaring a security issue resolved.
